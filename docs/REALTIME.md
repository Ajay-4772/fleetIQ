# VEHYRON — Real-Time Streaming & Event Architecture

## 1. Overview
VEHYRON implements a reactive, sub-second telemetry delivery pipeline from server to browser using **Server-Sent Events (SSE)** (`text/event-stream`). This avoids the high connection overhead of WebSockets while providing automatic reconnection, firewall compatibility, and native browser `EventSource` support.

---

## 2. Event Ingestion to UI Broadcast Flow

```
External Telematics System
        │ (POST /api/v1/events/ingest)
        ▼
EventProcessingService (Idempotency Cache & OEM Normalization)
        │
        ▼
CanonicalVehicleEvent Created & Persisted to DB
        │
        ▼
IssueDetectionService & Authoritative DecisionEngine
        │
        ▼
ActionItem Created / Updated & Persisted to DB
        │
        ▼
DashboardEventPublisher.publishEvent(CanonicalVehicleEvent event)
        │
        ▼
SseEmitterService.broadcast(event)
        │ (GET /api/v1/stream/events)
        ▼
Browser useSSE Hook (React State Delta Dispatch)
        │
        ▼
UI Components Re-render without Full Page Reload
```

## 3. SSE Stream Endpoint

### Endpoint
`GET /api/v1/stream/events` (and backwards-compatible `/api/dashboard/stream`)

### Authentication
- **Browser EventSource**: Passes JWT token as query parameter: `?token=<jwt_token>` or session bearer.
- **Anonymous / Public**: Stream endpoint is permitted in `SecurityConfig` to facilitate initial handshakes, with event payloads sanitized.

### Event Format
```http
event: VEHICLE_EVENT
data: {
  "eventId": "EV-TOYOTA-E2E-1",
  "vehicleId": "VH-1001",
  "eventType": "ENGINE_FAULT",
  "severity": "CRITICAL",
  "timestamp": "2026-09-25T07:20:00Z",
  "correlationId": "CORR-TOYOTA-E2E-1",
  "status": "NORMALIZED",
  "payload": {
    "speedKmh": 65.5,
    "batterySocPct": 78.0,
    "oilLifePct": 8.5,
    "faultCode": "P0300"
  }
}
```

## 4. Client Connection Lifecycle & Resilience

The frontend hook `useSSE.ts` manages connection state with resilience:

| Connection State | UI Badge | Description |
|---|---|---|
| **LIVE** | Green pulsating badge | SSE connection established and actively receiving heartbeats. |
| **RECONNECTING** | Amber badge | Connection severed. Client initiates exponential backoff reconnects (1s, 2s, 5s). |
| **OFFLINE** | Red badge | Reconnect attempts exhausted or backend unavailable. |

> **Rule**: The UI never falsely displays "Real-Time Stream" when the underlying event channel is offline or reconnecting.

---

## 5. Broadcast Event Types
- `CONNECTED`: Initial handshake confirmation sent upon emitter registration.
- `VEHICLE_EVENT`: Canonical telemetry event received and normalized.
- `CRITICAL_ALERT`: Real-time notification for CRITICAL severity anomalies requiring operator triage.
- `ACTION_CREATED`: A new operational action generated by the decision engine.
- `ACTION_UPDATED`: Action status change (e.g., OPEN → IN_PROGRESS → RESOLVED).
- `HEARTBEAT`: 25-second keep-alive ping preventing proxy/gateway timeouts.
