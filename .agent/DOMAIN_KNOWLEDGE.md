# FleetIQ — Domain Knowledge Base

**Domain Area**: Connected Vehicle Telematics, Multi-OEM Normalization & Intelligent Action Prioritization  
**Verification Date**: September 25, 2026

---

## 1. Verified Core Domain Concepts

### 1.1 Vehicle
The master physical asset representing an active fleet vehicle.
- **Primary Identifier**: 17-character standard Vehicle Identification Number (`VIN`).
- **Powertrain Classification**:
  - `BEV`: Battery Electric Vehicle (e.g., Tesla Model 3, Ford F-150 Lightning).
  - `ICE`: Internal Combustion Engine (e.g., Ford Transit, Toyota Camry).
  - `PHEV`: Plug-in Hybrid Electric Vehicle (e.g., Toyota Prius Prime, BMW 330e).
- **Operational Statuses**:
  - `ACTIVE`: Vehicle is in service, operational, and safe to dispatch.
  - `MAINTENANCE_REQUIRED`: Vehicle has non-grounding faults or scheduled service due.
  - `GROUNDED`: Severe safety/mechanical fault detected; vehicle must not be operated.
  - `OUT_OF_SERVICE`: Decommissioned, in depot maintenance, or undergoing repairs.

### 1.2 Original Equipment Manufacturer (OEM)
Automotive manufacturers with distinct, proprietary telemetry protocols and data formats.
- **Currently Implemented**:
  - `TESLA`: Flat battery-centric JSON with state-of-charge (`battery_level`), charging status, and proprietary alert codes.
  - `FORD`: Ford Pro telematics schema with nested fuel, oil life, and SAE J2012 Diagnostic Trouble Codes (DTCs).
  - `BMW`: BMW CarData schema containing vehicle status, CBS (Condition Based Servicing), and brake pad wear wear indicators.
  - `TOYOTA`: Toyota Connected Services schema reporting hybrid battery health, fuel economy, and standard OBD-II fault codes.
- **Proposed OEMs (Future Expansion)**:
  - `FREIGHTLINER` / `VOLVO_TRUCKS` (Heavy duty J1939 protocols).

### 1.3 Vehicle Event & Raw Ingestion Record
- **Raw Ingestion Record**: Raw, unprocessed JSON payload captured upon ingestion (`RawIngestionRecord`), preserved for auditability and replay.
- **Event Source**: Origin of incoming telemetry:
  - `SIMULATOR`: Synthetic multi-OEM event streams generated with deterministic seeds.
  - `REST_INGESTION`: Direct HTTP POST ingestion from simulated OEM webhook endpoints.
  - `STREAMING_QUEUE_PROPOSED`: Kafka / RabbitMQ message brokers (Proposed for distributed phase).

### 1.4 Normalized Event (Canonical Vehicle Event)
- **Canonical Model (`CanonicalVehicleEvent`)**: The unified enterprise representation that eliminates OEM schema disparity.
- **Standardized Metric Units**:
  - Speed: Kilometers per hour (`km/h`).
  - Odometer: Kilometers (`km`).
  - Fluid / Battery Levels: Percentage (`0.0% – 100.0%`).
  - Tire Pressure: Pounds per square inch (`PSI`).
  - Coordinates: Decimal latitude and longitude (`WGS 84`).

### 1.5 Event Types & Severity Levels
- **Event Types**:
  - `TELEMETRY`: Periodic heartbeat updates (speed, coordinates, SoC, fuel).
  - `DIAGNOSTIC_FAULT`: On-board diagnostic alert or DTC triggered.
  - `BATTERY_CRITICAL`: High-voltage battery SoC dropped below reserve safety threshold (< 10%).
  - `SAFETY_ALERT`: Sudden deceleration, stability control event, or airbag warning.
  - `MAINTENANCE_DUE`: Routine distance or fluid degradation interval reached.
- **Severity Levels**:
  - `CRITICAL`: Immediate safety hazard, thermal runaway risk, brake failure, or vehicle shutdown.
  - `HIGH`: Major component degradation requiring service within 24 hours.
  - `MEDIUM`: Non-critical maintenance alert (e.g., oil life < 20%, tire pressure delta).
  - `LOW`: Informational telemetry notification or minor routine warning.
  - `INFO`: Normal status report.

### 1.6 Action & Priority
- **Action Item (`ActionItem`)**: A prioritized operational work order dispatched to fleet operators.
- **Action Types**:
  - `GROUND_VEHICLE`: Immediate dispatch hold; driver must pull over safely.
  - `ROUTE_TO_CHARGER`: Reroute BEV to nearest fast charger due to depleted battery.
  - `SCHEDULE_MAINTENANCE`: Book vehicle into maintenance shop within 48–72 hours.
  - `INSPECT_BRAKES`: Schedule immediate brake caliper/pad inspection.
  - `CLEAR_FAULT`: Transient sensor glitch cleared after verification.
- **Priority Levels**:
  - `CRITICAL` (Score 90–100): Safety or catastrophic powertrain failure.
  - `HIGH` (Score 70–89): Imminent breakdown risk.
  - `MEDIUM` (Score 40–69): Preventive servicing.
  - `LOW` (Score 0–39): Informational / backlog.
- **Priority Scoring Formulation**:
  $$\text{Score} = (\text{SeverityWeight} \times 0.40) + (\text{ImpactCostFactor} \times 0.35) + (\text{UrgencyFactor} \times 0.25)$$

### 1.7 Decision, Decision Reason & Fallback
- **Decision (`Decision`)**: The computed output associating an event with a concrete action recommendation, estimated confidence, and rationale.
- **AI Decision (`AI_JEV`)**: Generated by calling external cognitive AI services, analyzing complex multi-variate telemetry patterns.
- **Deterministic Fallback (`DETERMINISTIC_RULES`)**: Pure, reproducible automotive heuristic rules executed locally without external network dependencies.
- **Decision Reason**: Plaintext explanation stating exactly which fault code, threshold, or sensor metric triggered the action.

### 1.8 Processing States
- **Event Lifecycle**: `RECEIVED` -> `NORMALIZED` -> `DIAGNOSED` -> `DECIDED` -> `ACTION_CREATED` -> `STREAMED`.
- **Action Lifecycle**:
  - `PENDING`: Newly created action awaiting operator review.
  - `IN_PROGRESS`: Operator or technician assigned; work underway.
  - `RESOLVED`: Maintenance completed and vehicle returned to active status.
  - `DISMISSED`: Operator audited and suppressed false positive or transient warning.
